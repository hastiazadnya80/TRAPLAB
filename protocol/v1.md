# C-Lite v1 — implementation protocol

This is a prospective protocol. No Beam results exist until a live run completes.
Pilot data are separate from main data. Any protocol change requires a new output
directory and source identity. Main settings: 5 independent trajectories × 12
items × 3 families × 2 arms = 360 evaluated items. Rounds contain 4 items.
Both arms share one story pool, one deterministic gate and one parameter space.

## Identification

Simpson questions explicitly specify either a complete unconfounded DAG with
pre-treatment Z and pooled target weights, randomized T with downstream Z and a
possible direct effect, or the union of exactly those two models. The last case
is answerable only if both models give the same registered answer. Arbitrary
unstated causal models are not assumed identifiable. A saturated discrete SCM
can reproduce these tables using independent uniform exogenous variables and
inverse-CDF assignments in the stated DAG order.

Collider data come from X~Bernoulli(px), Y~Bernoulli(p0+beta*X), and selection
S~Bernoulli(sXY), with independent exogenous variables. beta may be negative.
Selection on X preserves Y|X; joint selection with unknown propensities does not
identify population association. All displayed selected cells must be >=20.

RTM uses U~N(0,rho), independent e0,e1~N(0,1-rho), B=U+e0,
F=U+e1+delta*T, selecting B<-threshold. Baseline SD is 1. Conditional means
are analytic truncated-normal expectations. Reliability and untreated change are
not exposed in no-control questions. Randomized controls identify the effect
from visible difference-in-differences. Higher outcome is explicitly better.

Counts are exact expectations displayed to 2 decimals; means to 3 decimals.
Answer keys use Decimal arithmetic on displayed values. There is no sampling
uncertainty in the displayed tables. Differences with |d|<.01 are no difference,
.01<=|d|<.03 are rejected, |d|>=.03 have a sign. RTM uses .05 and .2 instead.
Both Simpson candidate estimands must pass the ambiguity gate.

## Search and metrics

Random draws are independent uniform draws on the documented numeric ranges,
rounded as in sampling.py, and uniform categorical choices; rejection sampling
conditions this distribution on the shared validity gate. Adaptive proposals use
the same support but need not use that distribution. Each arm rejects repeated
fixed-bin parameter cells plus story within its independent trajectory.

Simpson bins: role, floor(n/500) for a0,a1,b0,b1 and floor(rate*5) in that order.
Collider bins: selection, floor(px*5), floor(p0*5), floor(beta*5), and floor(s*4)
for 00,01,10,11. RTM bins: design, floor(rho*5), floor(threshold*2), floor(delta*5).
Story is excluded from the distinct-failure identity. Bins are coarse operational
definitions of novelty, not proof of distinct underlying reasoning mechanisms.

Designer receives previous-round params, tags, solver answers and statuses only.
It never receives solver explanations. Each round has a fixed proposal cap;
failure to fill a round stops the run as incomplete. Invalid proposals cost
designer tokens and are logged, but do not consume solver evaluations. No random
fallback is substituted for an adaptive failure. The current main cap is 12.
This policy must be assessed in the pilot before freezing the main configuration.

Primary discovery metric is number of distinct wrong-answer cells / actual solver
calls including retries. Also report the per-evaluated-item rate. Operational
failures remain in the denominator but are separate statuses.
Also report actual solver attempts (including retries), all designer/story calls,
tokens and latency. Dollar costs require actual provider pricing, not an assumed
rate. Report label distributions and a majority-label baseline when interpreting
accuracy. Matched trajectory seeds support paired comparison; dependence within
trajectories is handled with trajectory-level paired bootstrap. Five trajectories
provide limited uncertainty estimation. Wilson item intervals are descriptive,
especially for adaptive data and discovery events.

## Transport and replay

Model: reflection/Beam-1.0-501B-A23B, reasoning_effort=low, 4096 completion tokens.
Provider support must be confirmed by a live smoke test. A length completion is
retried once with 8192. Both responses count toward usage. Strict JSON parsing
rejects extra keys, markdown, duplicate keys and invalid answer labels. Missing
reasoning_content is permitted and is not imputed. Persisted calls contain safe
response fields, not Authorization headers. A process crash during an in-flight
remote request can incur usage that was never received; resume cannot promise
exactly-once billing. Single writer per run directory is required.

## Scope of the initial implementation

Implemented: three generators, gate, shared stories, live API adapter, deterministic
grader, adaptive/random runner, replay, uncertainty, read-only atlas/browser, and
local four-config dataset packaging. Offline fixture runs are visibly marked DEMO;
their adaptive proposals are synthetic random draws, not Beam designs.

Extensions implement a seeded 10% main-item sample with two extra calls (three
observations total); numerical-feedback revision on up to 60 wrong and 60 matched
correct answers; 20 distinct numeric bases × 5 stories × 3 repeats; and three
Simpson configurations × 11 grid points × 3 repeats, minus gate rejections.
No extension has been run on Beam yet. No LLM judge or tuning.

Story sensitivity holds option ordering fixed within each base and uses a
two-sided Monte Carlo permutation test, 2000 permutations, permuting answer labels
within base while preserving three repeats per story. The statistic is mean
across-story disagreement minus within-story disagreement, equally weighted by
base. Only bases with all 15 valid responses enter the test; exclusions are
reported. This missingness can limit interpretation. Correctness per story is
also available in the stored traces.

Flip configurations vary p_a0 on .05,.14,...,.95 with equal cell sizes, p_a1=.2,
and p_b0=p_b1=.25,.35,.45. Adjusted-effect roots are .3,.5,.7 analytically.
Ambiguity-band points are logged in the fixed plan and receive no solver calls.
Two of three valid answers are required for majority. More than one binary
crossing is unstable; none is no_flip; unresolved points prevent a flip estimate.
A single crossing is reported as an interval and a discrepancy interval relative
to the analytic zero. No binary search or artificially precise point estimate is
used. The no_difference interval and rejection bands remain explicit.
